Project Overview & Objectives

Solving real-world food court queueing and ordering challenges through modern web technologies.

🎯 Core Problem Statement

  • Traditional food courts experience severe rush-hour congestion and long checkout queues.
  • Manual paper ordering leads to order mismatches and delayed updates.
  • Static menus lack live search, dietary filtering, and customizable portion sizes.

🚀 Solution & Key Objectives

  • Build a responsive Single Page Application (SPA) using React 18.
  • Implement high-performance RESTful API endpoints with Node.js & Express.
  • Manage persistent NoSQL data using MongoDB Atlas & Mongoose ORM.
  • Provide real-time live dish search, category tabs, and 🟢 Veg / 🔴 Non-Veg diet toggles.
  • Implement secure user authentication using JWT & Bcrypt.

📐 Architecture & Data Flow
Slide 3 / 13

System Architecture & End-to-End Data Flow

Decoupled client-server model ensuring high scalability and fast response times.

🔄 Architectural Workflow

  • User Layer: Browser renders React SPA with responsive Bootstrap 5 styling.
  • State Layer: React Context Reducer handles cart state locally before dispatching orders.
  • API Layer: Express.js server intercepts requests (`/api/foodData`, `/api/loginuser`).
  • Security Layer: Express-Validator validates payload; Bcrypt hashes passwords; JWT issues tokens.
  • Data Layer: Mongoose queries MongoDB Atlas cloud database with automatic fallback initialization.

🌐 API Endpoint Map

Method Endpoint Description
POST `/api/foodData` Fetches menu items & category dataset
POST `/api/createuser` Registers user with hashed password
POST `/api/loginuser` Authenticates & issues JWT auth token
POST `/api/cartorderdata` Submits checkout order to database

🔒 Security & Authentication
Slide 8 / 13

Password Hashing & JWT Authentication

15-20% Code Highlight: User Login & Bcrypt Password Hashing (`server/Routes/CreateUser.js`)

🔑 Security Strategy

  • Passwords hashed using **BcryptJS** with salt factor 10.
  • Request validation handled via **express-validator** (Email format & Min Password Length).
  • Stateless authentication token issued via **JSON Web Token (JWT)** upon successful login.

💻 Authentication Handler Code

router.post("/loginuser", body('email').isEmail(), body('password').isLength({ min: 5 }), async (req, res) => { let userData = await User.findOne({ email: req.body.email }); if (!userData) return res.status(400).json({ errors: "Invalid Email" }); // Compare hashed password const pwdCompare = bcrypt.compareSync(req.body.password, userData.password); if (!pwdCompare) return res.status(400).json({ errors: "Incorrect Password" }); // Generate JWT token const authToken = jwt.sign({ user: { id: userData.id } }, jwtSecret); return res.json({ success: true, authToken }); });

Global Cart State Reducer (`client/src/components/ContextReducer.js`)

15-20% Code Highlight: Centralized Cart State Provider with Actions

🛒 State Operations

  • `ADD`: Appends selected dish, portion size, and calculated total price to global cart array.
  • `REMOVE`: Deletes item from cart by array index.
  • `DROP`: Clears cart upon successful order checkout.
  • Exposes `useCart()` and `useDispatchCart()` custom hooks across components.

💻 Context Reducer Source Code

const CartStateContext = createContext(); const CartDispatchContext = createContext(); const reducer = (state, action) => { switch (action.type) { case "ADD": return [...state, { id: action.id, name: action.name, qty: action.qty, size: action.size, price: action.price, img: action.img }]; case "REMOVE": return state.filter((_, index) => index !== action.index); case "DROP": return []; default: return state; } };
