Project Vision & Core Objectives

Solving real-world food court queueing and ordering challenges through modern web technologies.

🎯 Problem Statement

  • Traditional food court canteens suffer from long peak-hour queues.
  • Manual paper ordering causes item mismatches and slow order status updates.
  • Static printed menus lack dietary filtering, portion sizing, and real-time search.

🚀 Project Objectives

  • Develop a Single Page Application (SPA) using React 18.
  • Build REST APIs with Node.js & Express Framework.
  • Store persistent NoSQL documents in MongoDB Atlas cloud.
  • Implement real-time search, category tabs, and 🟢 Veg / 🔴 Non-Veg toggles.
  • Provide secure authentication with JWT & Bcrypt.

🗺️ User Journey & Workflow
Slide 3 / 14

End-to-End User Journey (Start to End)

Complete functional workflow from account creation to order fulfillment.

🔄 Step-by-Step Platform Journey

STEP 1 Account Creation (`/createuser`): New users sign up with Name, Email, Password, & Location. Password is encrypted using Bcrypt.
STEP 2 Secure Login (`/loginuser`): User credentials are verified against MongoDB; JWT authToken is issued & stored in LocalStorage.
STEP 3 Menu Browsing & Search (`/`): Users explore 15+ dishes, filter by Category Tabs or toggle 🟢 Veg / 🔴 Non-Veg diets.
STEP 4 Portion Customization & Cart (`ADD`): Users select portion sizes (Half/Full), quantities, and dispatch items to React Context Cart Reducer.
STEP 5 Order Checkout (`/cartorderdata`): Orders are submitted to MongoDB server and saved in user order history.

🛒 State Reducer
Slide 9 / 14

Global Cart Context Reducer (`ContextReducer.js`)

Centralized React State provider managing shopping cart items.

📦 Cart State Actions

  • `ADD`: Appends selected dish, size, and price to global cart array.
  • `REMOVE`: Deletes item from cart array by index.
  • `DROP`: Clears cart array upon successful checkout.
  • Exposes `useCart()` and `useDispatchCart()` custom hooks.

💻 Minimal Reducer Code

const reducer = (state, action) => {
  switch (action.type) {
    case "ADD":
      return [...state, { id: action.id, name: action.name, qty: action.qty, size: action.size, price: action.price }];
    case "REMOVE":
      return state.filter((_, i) => i !== action.index);
    case "DROP":
      return [];
    default:
      return state;
  }
};

const UserSchema = new Schema({
  name: { type: String, required: true },
  email: { type: String, required: true, unique: true },
  password: { type: String, required: true },
  location: { type: String, required: true },
  date: { type: Date, default: Date.now }
});
module.exports = mongoose.model("user", UserSchema);

⚡ Failover Resilience

  • Automatic connection retry timeout configured at 5000ms.
  • Includes fallback food dataset initialization ensuring 100% demo availability.
  • No SQL injection vulnerabilities due to Mongoose ORM parameter sanitization.
